# Known issues and fixes

This log records user-visible issues found while adapting the MindMesh source into this focused clone. It describes the fixes currently represented in the code; provider outages and private/removed content remain external limits.

| Area | Observed issue | Fix / current behavior |
| --- | --- | --- |
| Dashboard quick actions | React warned that repeated display text could become a duplicate child key. | The Add Source menu now keys each item by its destination route, which is a stable unique identity independent of the visible label. |
| YouTube / Instagram | Website processing could stop immediately with a generic `404 Not Found` while the companion used the mobile quick-save route. | The website pages call the clone's selected YouTube and Instagram API routes; the companion keeps its own quick-save receipt route, which dispatches into those same ingestion handlers. Check the active API base URL and `/health` if a 404 returns again; the API and website must be started from this clone, not another checkout. |
| Semantic search | Short names such as “Jay” or “Riya Prajapati” returned unrelated nearest-vector results with misleading confidence labels. | Ranking now uses lexical/title evidence alongside vector similarity and shorthand expansion. Short person-name queries require a name occurrence in saved text; the score is presented as relevance, not probability. Longer natural-language questions still allow semantic paraphrases. |
| Ask AI search integration | Search was a separate destination from chat, making users switch pages to find saved sources. | `/search` now redirects to `/chat`; answers include ranked source cards with thumbnails, relevance labels, and direct original-source links. |
| Ask AI citations | Model output could show raw bracket references such as `[2]` without a useful explanation. | The answer renderer maps valid citation markers to the returned source records, and each response's source cards expose the actual title and link. Invalid or missing references are not source links. |
| Ask AI conversation | Earlier messages temporarily disappeared while a later question was generating. | The chat keeps the full conversation and appends a per-turn loading state for the pending response. |
| Ask AI quick actions | Export, comparison, or simplification could produce a generic “no relevant content” response even when the action was not the real problem. | Follow-up actions are sent through the same grounded chat flow and rely on retrieved saved context; when that context is absent, the assistant should say it has no matching saved knowledge instead of inventing an answer. Markdown export is offered from the generated answer when available. |
| Knowledge Graph | Extracted YouTube concepts were displayed in the Instagram cluster, and older sources kept incorrect placement. | Concepts are placed using source-tagged relationships checked against each source's platform. `POST /api/graph/rebuild` regenerates legacy relationships from saved source metadata and indexed chunks. See [Knowledge Graph](features/knowledge-graph.md). |
| Companion OAuth | Google sign-in returned to the browser instead of the native clone app. | The clone uses its own Android application ID and `mindmeshclone://auth/callback` deep link. Add that URI to the Supabase redirect allowlist and ensure the Android callback intent filter is installed in the build. Browser account selection may still be used by the provider, but successful auth should deep-link back into the companion. |
| Companion saves | A shared link could remain in a generic processing state or be marked failed without enough detail. | The companion persists queue states in Room, retries network work with WorkManager, uses idempotency keys, and polls backend processing status. It shows recorded outcomes such as Backend offline, Needs sign-in, Processing, Synced, or Failed instead of treating enqueue acceptance as completed ingestion. |
| Analytics authorization | Analytics must be available in the admin portal without exposing user names or letting a guessed URL grant access. | Collection is opt-in and low-detail; admin aggregates require server-verified owner/admin scope. Local mode uses ignored SQLite data; cloud mode requires the documented database migration. |

## Limits when diagnosing a recurrence

An error message alone does not establish whether a URL was invalid, provider-blocked, the backend was unavailable, or the wrong server checkout was running. Check the browser/network response, API logs, configured API URL, and the job's recorded status before treating a recurrence as the same defect. Never paste secret environment values into issue reports.
